✨ AI

Powers the 💬 AI Assistant panel, and — for Open WebUI or Gemini — the ✨ Generate image buttons (Ollama has no image-generation API of its own, so it can't power those even when it's the chat provider). API keys are encrypted before being stored — this page never displays a saved key back to you, only whether one is set. Use "Load Models" to pull the live model list from that provider instead of typing a name — it uses whatever's currently in the URL/key fields above it, even if you haven't saved yet.

Open WebUI

Open WebUI doesn't report per-model capabilities the way Ollama does, so models aren't tagged here — check the model itself supports image input if you're attaching screenshots in the chat.

Used by the ✨ Generate buttons (Image/Banner/Card) — sent as the model field to Open WebUI's own image-generation API, which proxies to whatever backend it's configured with (ComfyUI, AUTOMATIC1111, ...). This app has no visibility into that backend or its workflow — if generation fails, check Open WebUI's own Image Generation settings first. A reference/"keyframe" image is sent along when the tool provides one, but whether the backend actually uses it (image-to-image) instead of ignoring it (text-to-image only) depends entirely on how that workflow is built — not something this app can detect.

Used by the 🎥 Generate button on Media Player sections. Unlike image generation, Open WebUI has no built-in video API — this instead names a model that has a video-generation Tool attached in Open WebUI's own Workspace → Tools (Open WebUI's chat-completions API only executes a Tool when the request is tied to a real chat, so this runs as a background task and picks up the resulting video file once it's ready — same "no visibility into the backend" boundary as image generation: whatever that Tool actually calls (ComfyUI, a hosted API, anything) is entirely up to how it's configured on the Open WebUI side).

Ollama

Self-hosted, no API key needed for a LAN/localhost instance.

Models tagged (vision) can take image input (Ollama reports this itself, via its model capabilities — not every model that can will be tagged, only the ones Ollama confirms).

{# Two limits worth knowing BEFORE choosing this, rather than meeting them as things that seem broken. Both are Ollama being what it is, not this app failing -- but an owner who is not told cannot tell those apart, and "the Generate button does nothing" reads as a bug every time. #}

Ollama cannot make pictures. It has no image-generation API at all, whatever model is loaded, so the ✨ Generate buttons (Image, Banner, Card, a product photograph) are not offered while it is the provider. If your setup is backed by ComfyUI or similar, that is reachable through Open WebUI: put it in front of Ollama and choose it here instead — it passes image requests on to the backend and still uses your Ollama for chat.

A small model follows instructions less reliably. Asked to do something it cannot map to one of the assistant’s tools, a self-hosted model will often return nothing at all rather than say it is unsure. This site says so when that happens now, instead of showing you an empty answer — but the cure is a larger model, or asking one step at a time in plainer words.

Google Gemini

Image generation needs a Gemini account with billing enabled — the free tier covers chat but not image output, and a free-tier key will fail with an error when you click Generate rather than up front here.
