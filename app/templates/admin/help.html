Help

This is a custom-built, self-hosted CMS — not WordPress, not any other platform. There's no cPanel, no plugin marketplace, no host-provided admin panel. Everything about managing this site is on this one page — the 💬 AI Assistant is grounded on the same information, so you can ask it any of this in your own words too.

Pages & Content

A page is made of sections — empty frames, nothing more. "+ Add Section" (on the live page, while editing) adds a blank frame with no content of its own.

  • A section's own toolbar has a Divide control to split it into 1–6 side-by-side cells (columns); each cell can itself be split into rows.
  • Content only comes from Tools, dragged (or tapped) from the 🧰 Tools panel into a frame or a specific cell — this replaces just that cell, not the whole frame.
  • Frames/cells are reordered by dragging the ⠿ handle.
  • Every section can set its own width (Auto / Full width / Custom %) from its own toolbar, or inherit the site-wide default (Design → Layout).

Default Tools

  • Text — rich WYSIWYG (the same editor writes a blog post): bold/italic/underline/lists/headings/links/align/fonts/colors/insert-image/insert-icon (a large curated emoji picker).
  • Image — size/shape mask/link/animation, plus an AI ✨ Generate button.
  • Media Player — YouTube link, or an uploaded video/audio file.
  • File / Download — a list of files to download, one line each like Contact Info: upload a file or choose one from the Media Library, pick its icon (or leave it to follow the file's type — PDF, DOC, XLS…), and give it a name to show or keep the file's own. Shown as cards, buttons, plain links or icons. Files keep their own names when downloaded.
  • Table (Data) — click any cell to type in it; the tool's own controls set the look (bordered/striped/colored header/plain), turn the header row on or off, and add or remove rows and columns.
  • Video Gallery — a grid of YouTube clips: paste a link for each one, give it an optional caption, and choose how many sit side by side. Visitors play a clip in a popup without leaving the page.
  • Accordion — five picture panels, each with its own image (upload or AI-generate) and caption. Three displays: Panels (hover to expand), Carousel (swipe or arrows), Masonry (staggered grid) — the same panels either way, so switching display never loses anything. Tick "Click to enlarge" and visitors can click any panel to see the full picture in a popup — that works with all three displays.
  • Menu — pick pages to link, plus custom links, dividers, and per-item icons. Styles: Plain / Buttons / Pill badge on the page you are on / Dropdown (with submenus). Button style: Solid, Outline, Soft, Floating, Tabs, Fade. Submenu style (Dropdown only): Card, Minimal, Dark, Bordered, Pill.
  • Breadcrumb — size/style.
  • Language — lets a visitor switch the site's language, showing whatever languages you've enabled (Design → Languages).
  • Site name, Version — the site's own name (follows a rename), and the version of gmsCms the site runs on (follows an upgrade). Both are filled in when the page is drawn; neither is typed.
  • Banner — background image + overlay headline/text, optional shape mask, AI ✨ Generate button.
  • Card — a background shape (rectangle/rounded/oval/circle/pill) with an optional custom color and/or AI-generated image, that you write text directly over.
  • Divider — a styled horizontal rule: line style/width/spacing/color.
  • Embed — raw HTML/script. Only for third-party widgets that need real embed code (a Cal.com booking calendar, a Stripe button) — never for styling or layout, which always has a dedicated tool instead.
  • FAQ Content / FAQ Reader — Content holds your questions and answers as one document (shown read-through or folded into rows); a Reader elsewhere shows a chosen set of them, so a wording change follows everywhere it's repeated.
  • Search — a search box that filters whatever on the page has said it is searchable (e.g. FAQ answers).
  • Blog — shows a blog's posts wherever you drop it.
  • Contact Form — a form visitors write to you with (emailed to your contact address; rate-limited and spam-trapped).
  • Contact Info — your phone, email, address and social row, laid out.

Ready-made content blocks

Filled in through a simple form, never by typing markup: Pricing tiers, Testimonial, Numbers (stats), Logo row, The team, Tags, Timeline, Call to action, and Email sign-up (a double-opt-in newsletter sign-up).

Shop tools

Available once Stripe is connected (Commerce): Shop (your product catalogue), Buy Button (one product), and Basket (a floating cart). See Commerce, above.

Default tools always exist and can't be removed and can't be created — but a custom tool from a Template Package, or one someone shares with you, can be imported via the Tools panel's "📦 Toolkits" section, and deleted again afterward.

The Live Page Edit Bar

While logged in and editing, three tabs dock to the right edge of every page:

  • 💬 AI Assistant — this chat. It can look at real page/section content and propose edits (nothing is ever applied without you clicking Apply), and can take an attached image (🖼️ button) as visual guidance.
  • 🧰 Tools — the tool palette described above.
  • 🎨 Colors — the active theme/template's colors: pick a curated preset collection, or fine-tune each color under "Advanced". Per the currently active template, not a Dashboard setting.

Drag the small handle in a panel's top-left corner to resize it wider/taller — this is remembered across visits.

The bar at the very top also has a screen-size dropdown (Desktop / Laptop / Tablet / Mobile). It narrows the canvas while you edit, and when you switch to Viewing it opens the page in a real device frame of that width, exactly as a visitor sees it — a real preview rather than the page squeezed narrow, so anything that changes on a small screen actually changes.

Where everything is

The Dashboard is a row of buttons. Each opens its own screen, and the bigger ones group related screens behind tabs along the top.

  • 🎨 Design — five tabs. Pages adds, renames, reorders and deletes pages and sets the home page. Templates is your library of looks: activate one, export it as a .zip, import somebody else’s, or save your current site as a new template. Layout decides where the header, sidebars and footer sit. Theme Generator writes a whole look and its words from a description, and Languages is where you enable the languages a visitor can switch between and have the site translated.
  • 📰 Blog — your blogs and every post in them. A blog is a named set of posts with its own address; the Blog tool shows one wherever you drop it, on as many pages as you like.
  • 🖼️ Media — every picture and file on the site: the ones you uploaded or generated, and the ones each installed template brought with it. A template’s own pictures are marked 🔒 and cannot be deleted here — they belong to the template, which would be left with a hole in it.
  • 🔌 Connections — Stripe, Cal.com and your AI provider, with a Test button beside each. “Connected” means a real call succeeded, not that a key is stored.
  • ✉️ Email — four tabs. Newsletters writes and sends them, Email list is who has confirmed, System emails is the wording of the messages your site sends itself (orders, sales, sign-ups), Sending email is the mail server it all goes through.
  • 🛍️ Commerce — four tabs. Products is what you sell and what each sale delivers, Orders is every sale (filter by buyer, product, kind or date), Bookings is your diary, and Store settings is your currency, delivery, and how far ahead sessions can be booked.
  • ⚖️ Legal pages, 💾 Backups — written from your own details, and a copy of everything you can restore.
  • 🕒 Schedules — the times this site acts at, named once and reused wherever a time is picked: sending a newsletter, publishing a post, running a backup. A second tab lists everything on the clock and everything that has been.
  • 📋 Activity — a log of everything the site has done (what a template changed, what was removed, what was sent), newest first.
  • 📈 Visitors — how many people visited, when, and roughly which countries. It is an anonymous count — no IP address or visitor is ever stored, only totals per day, country and page, and your own visits (while signed in) are not counted. Countries are worked out on your own server from a bundled offline database, so nothing about a visitor is sent anywhere.
  • ♥ Support — gmsCms is free. This is where to show a little appreciation if you like (PayPal or crypto — a gift, never required), and where you can switch off the small credit line under your footer.

The bar at the very top is the same on every screen while you are signed in — Dashboard, Account, Media Library, Help, Support, Log out — on the admin screens and on your live site alike. The number at its right end is the version of gmsCms this site runs on; the Version tool (Tools → Navigation) puts the same number on the page itself, wherever you drop it.

Pages are just pages

What a page can do comes from the tools on it, not from a kind chosen when it was made. Creating one lets you start it as a Blog, FAQ or Contact page, but that only decides which tools are already there: you can add a second blog beside the first, put an FAQ on your home page, or move any of it later.

Two things are decided per page rather than by its type: whether it appears in a menu (you tick it), and whether visitors can read it at all (“public” — a private page opens for you and 404s for everybody else).

Blogs and FAQs belong to your site, not to a page

A blog is a named set of posts, shown wherever you drop a Blog tool — on one page or several, without copying anything. Questions work the same way: an FAQ Content tool holds them, and an FAQ Reader elsewhere shows the ones you tick. Edit a question where it was written and every page repeating it follows.

Newsletters and the emails your site sends

A newsletter is not a page. Most page tools cannot survive an inbox — a Shop or a Blog is filled in when a page is drawn, and there is nothing to fill it in from inside an email — so a newsletter is written from a layout instead: a shape built for email, with slots you fill in.

  • Email → Newsletters → pick a shape (a letter, one story with a picture, two things side by side, or an announcement), fill it in, Preview to see exactly what will land, then send.
  • You can also send a blog post as a newsletter. A post already has a title, a date, a permanent address and an online copy, so it is an issue without inventing one.
  • Only people who have confirmed their address are ever written to. Signing up sends one invitation; nothing else goes out until it is answered.
  • Every newsletter carries your postal address and an unsubscribe link, by law. Both are added for you and cannot be edited away. The greeting and sign-off around them are yours (Email → Newsletters).

Order confirmations, the note telling you about a sale, and the two subscription emails are dressed in your site’s colours and fonts too — but they carry no unsubscribe link, because there is nothing to unsubscribe from. A receipt is one half of something the buyer just did.

Account & Admins

All on the Account page (top nav).

  • Change Password — current password, new password, confirm. This is the password reset flow — there's no email-a-link option, no cPanel. If a password is forgotten entirely, another admin can remove and re-add that account; with no other admin, whoever runs the server runs docker compose run --rm web python -m app.recover_admin <username>, which issues a new one-use password the same way a first boot does.
  • Sign-In Method — once Google Sign-In works, password sign-in can be disabled entirely (Google-only from then on), and re-enabled the same way.
  • Admins — everyone who can sign in and fully manage the site (no limited/read-only role). Add an admin (username/password, optionally a linked Google account) or remove one. The last remaining admin can't be removed, and you can't remove your own account while logged in as it.
  • Google Sign-In — Client ID/Secret for Google OAuth (encrypted once saved). Once set, admins can sign in with Google instead of a password.

AI Settings

🔌 Connections → the ✨ AI card.

  • Provider — Open WebUI, Ollama, or Google Gemini. Fill in its URL/key, then use "Load Models" to pick from a live list instead of typing a name. This is what powers the 💬 AI Assistant chat.
  • Image generation (the ✨ Generate buttons on Image/Banner/Card) — works via Gemini (needs a billing-enabled account — the free tier doesn't support image output) or Open WebUI (proxies to whatever image backend it's configured with, e.g. ComfyUI — set an "Image Generation Model/Workflow" name if it needs one). Ollama has no image-generation API of its own.
  • Video generation (the 🎥 Generate button on Media Player sections) — Open WebUI only, and only if a model there has a video-generation Tool attached (Workspace → Tools) — name that model as the "Video Generation Model". Runs as a background task on Open WebUI's side, so it can take several minutes, especially if its backend needs to wake up from idle first.
  • API keys are encrypted before being stored, and never displayed back once saved — only whether one is set.
